# 맞춰(MatchU) 5분 발표 — 최종 압축본

> 이 문서를 발표의 단일 기준으로 사용한다. 기존 `presentation-5min-guide.md`는 아이디어 저장소로만 남기고, 실제 PPT와 발표 대본에는 이 문서의 내용만 사용한다.

## 1. 발표에서 끝까지 유지할 한 문장

> **맞춰는 빈 시간을 찾는 캘린더가 아니라, 팀의 맥락을 반영해 실제로 성사될 회의를 결정하는 일정 조율 에이전트입니다.**

발표 전체를 다음 대비로 연결한다.

```text
기존 캘린더: 언제 비어 있는가?
맞춰(MatchU): 이 팀은 언제 만나야 하는가?
```

## 2. 제품 범위 — 발표에서 말할 것과 말하지 않을 것

### 현재 작동하는 MVP

- 로그인 화면 → 개인홈 → 그룹홈 이동
- 개인홈에서 그룹 생성 및 `영문 5자 + 숫자 5자` 참여 코드 발급
- 참여 코드 입력 후 해당 그룹 가입 및 그룹홈 이동
- 회의 제목, 주, 시간, 방식, 필수 참석자 입력
- 멤버별 `가능 / 조정 가능 / 참석 불가` 판정
- 전원 가능 → 조정 후 가능 → 필수 참석자와 최대 참석 인원 → 그룹 선호 순으로 후보 결정
- 추천 이유, 대안 후보, 조정·알림 대상 표시
- 사람의 확인 후 회의 확정 및 개인 일정에 반영
- 후보 계산 로직 테스트 6개 및 로그인·개인홈·그룹홈 검사 통과

### 구현됐지만 핵심 발표에서는 한 문장만 언급

- Supabase DB·RLS·참여 코드 RPC 설계
- OpenAI 추천 설명 API 경로
- Gmail 조정 메일용 Skill, 안전한 dry-run·draft 스크립트
- Google Calendar 실연동을 위한 어댑터 계약
- 주간 리포트와 출석률 데이터 구조

### 현재 데모에서 구현 완료라고 말하지 않을 것

- 실제 Google OAuth 로그인과 실시간 Calendar 동기화
- 웹사이트에서 Gmail 메일이 실제 발송됐다는 주장
- 출석률·개인 중요도가 현재 정적 최적화 결과를 직접 바꾼다는 주장
- AI가 현재 정적 데모의 시간 점수를 직접 계산한다는 주장
- 모든 캘린더 서비스가 이미 통합됐다는 주장

발표 원칙은 간단하다.

> **현재 화면에서 보이는 것은 “구현”, 연결 지점만 준비된 것은 “확장 계획”으로 구분한다.**

# 3. 최종 슬라이드 구성 — 총 4장

## 슬라이드 1 — 빈 시간은 보여도, 최선의 회의는 결정되지 않습니다

### 슬라이드의 역할

첫 45초 안에 사용자 문제, Behavior, Context, Goal과 장기 가치를 동시에 이해시킨다.

### 화면에 보일 문구

**제목**

> 빈 시간은 보여도, 최선의 회의는 결정되지 않습니다

**왼쪽 — 현재 Behavior**

```text
캘린더 확인
→ 단체 채팅에서 가능 시간 질문
→ 불참자에게 다시 확인
→ 한 사람이 수동으로 타협안 결정
```

**오른쪽 — 맞춰가 보는 Context**

```text
Busy / Free
필수 참석자
조정 가능한 일정
선호 요일·시간·회의 방식
```

**하단 Goal**

> 모두가 비는 시간보다, 실제로 성사될 회의를 찾습니다.

**Value–Term 그래프**

- 가로축: 반복 사용 빈도 낮음 → 높음
- 세로축: 실행 가치 낮음 → 높음
- 맞춰: 오른쪽 위
- 근거는 두 개만 표시한다.
  - 팀 회의는 매주 반복된다.
  - 충돌이 생길 때마다 판단과 커뮤니케이션이 필요하다.

### 발표 대본

> “기존 캘린더는 누가 언제 바쁜지는 알려줍니다. 하지만 누가 꼭 참석해야 하는지, 어떤 일정은 조정 가능한지, 전원이 안 될 때 어떤 선택이 공정한지는 결정하지 못합니다. 결국 한 사람이 캘린더와 단체 채팅을 오가며 타협안을 만듭니다. 맞춰는 이 반복적인 의사결정을 해결합니다. 그래서 일회성 빈 시간 검색이 아니라, 반복성과 실행 가치가 모두 높은 영역을 목표로 합니다.”

### 다음 장 연결

> “그렇다면 어떤 판단은 규칙이 하고, 어떤 판단은 AI가 해야 할까요?”

## 슬라이드 2 — 계산은 규칙으로, 해석과 중재는 AI로

### 슬라이드의 역할

Behavior, Context, Action, Goal, AI Tool을 하나의 흐름으로 보여주고 “왜 AI인가?”에 답한다.

### 화면에 보일 구조

```text
BEHAVIOR
반복되는 수동 조율
      ↓
CONTEXT
Busy/Free · 필수 참석자 · 조정 가능 · 그룹 선호
      ↓
RULE ENGINE
후보 생성 · 참석 가능 판정 · 우선순위 계산
      ↓
AI
자연어 조건 구조화 · 추천 이유 설명 · 개인별 중재 문구
      ↓
ACTION
후보 제안 · 대안 생성 · 사용자 확인 · 일정 확정
      ↓
GOAL
실제 참석 가능성이 높은 회의
```

### AI Tool 표기

```text
Deterministic Rule Engine
+ OpenAI Responses API
+ Google Workspace Skill/API 연결 지점
```

### 반드시 말할 구분

- 시간 겹침과 우선순위 계산은 규칙 엔진이 한다.
- AI는 자연어 요청, 추천 이유, 사람별 조정 문구를 담당한다.
- 메일 발송과 일정 확정은 사람이 마지막으로 확인한다.

### “AI가 반드시 필요한가?”에 대한 답

> “빈 시간 계산에 AI는 필요하지 않습니다. 하지만 ‘누가 꼭 참석해야 하는가’, ‘왜 이 후보가 더 공정한가’, ‘누구에게 어떤 대안을 요청할 것인가’를 자연어 맥락으로 처리하려면 AI가 필요합니다. 그래서 계산과 AI 역할을 분리했습니다.”

### 발표 대본

> “저희는 AI에게 시간을 계산시키지 않았습니다. 동일한 입력에 동일한 결과가 나오도록 후보 생성과 정렬은 규칙 엔진이 담당합니다. AI는 ‘이번 주 오후에 민재가 꼭 참석하는 한 시간 회의’ 같은 요청을 구조화하고, 이미 계산된 결과를 설명하며, 충돌한 멤버에게 보낼 조정 문구를 만듭니다. 마지막 확정은 사람이 합니다. 계산은 안정적으로, 중재는 유연하게 처리하는 반자동 에이전트입니다.”

## 슬라이드 3 — 한 번의 입력으로 후보 비교부터 확정까지 이어집니다

### 슬라이드의 역할

45~60초 녹화 영상을 크게 보여주며 작동하는 프로토타입 20점을 확보한다. PPT에는 작은 설명 카드 대신 영상과 한 줄 흐름만 둔다.

### 화면에 보일 한 줄

```text
그룹 선택 → 회의 조건 입력 → 최적 후보·대안 계산 → 확인 후 확정
```

### 최종 시연 순서

1. 개인홈에서 `해커톤 팀` 선택 — 4초
2. 그룹의 5명 멤버와 선호 시간 확인 — 5초
3. `새 회의 만들기`에서 날짜·길이·필수 참석자 입력 — 8초
4. `최적 시간 계산하고 확정` 클릭 — 3초
5. 추천 결과에서 다음을 확대해 보여주기 — 15초
   - 기본 데모의 `전원 참석 가능` 상태
   - 가능한 사람, 조정 가능한 사람, 참석 불가한 사람
   - 비교한 후보 수와 추천 이유
   - 다른 날짜의 대안 후보
6. 확정된 회의가 그룹 달력과 개인홈 일정에 반영되는 장면 — 10초

### 시연에서 빼는 장면

- Google 로그인 화면에 오래 머무르기
- 그룹 생성 폼을 처음부터 모두 입력하기
- DB나 코드 화면 보여주기
- 실제 연결이 확인되지 않은 Gmail 발송 장면
- 모든 탭과 모든 후보를 하나씩 설명하기

그룹 참여 코드는 발표의 핵심 가치가 아니므로 시간이 남을 때만 3초 정도 보여준다.

### 영상 위 발표 대본

> “개인홈에서 반복 회의를 하는 그룹으로 들어갑니다. 회의의 주와 길이, 방식, 필수 참석자를 설정하면 맞춰가 한 주의 후보를 모두 비교합니다. 전원이 바로 가능한 시간을 먼저 찾고, 없다면 조정 가능한 일정이 가장 적은 후보를 찾습니다. 그래도 어렵다면 필수 참석자와 최대 참석 인원을 지키고 다른 날짜의 대안까지 제시합니다. 사용자가 결과를 확인한 뒤에만 회의를 확정합니다.”

기본 시연 데이터에서는 `전원 참석 가능` 결과가 나온다. `일정 조정 필요`, `일부 참석`, `필수 참석자 불참` 분기는 자동 테스트로 검증했다고 슬라이드 4에서 설명한다. 기본 데이터가 아닌 결과를 영상에서 임의로 주장하지 않는다.

## 슬라이드 4 — 3시간 MVP에서 ‘조율 의사결정 루프’를 검증했습니다

### 슬라이드의 역할

평가 증거, Skill·Plugin, 팀 협업, 안전성, 장기 비전을 45~55초에 정리한다.

### 화면에 보일 내용

**검증한 것**

```text
개인홈 → 그룹홈 → 후보 계산 → 대안 설명 → 사람 확인 → 확정
```

**증거**

- 최적화 로직 테스트 `6 passed`
- 정적 페이지 검사 `3/3 passed`
- 브라우저에서 그룹 생성·가입·최적화 흐름 검증
- 콘솔 오류 `0`

**Skill / Plugin**

- Skill: 발표 구조를 정리하는 Presentations Skill 실제 사용
- Plugin: Browser Plugin으로 핵심 사용자 흐름을 실제 검증
- Gmail Skill은 실제 draft 실행 증거가 있을 때만 추가 표기

**4명 팀 결과 연결**

```text
기획·AI       문제 정의와 AI 역할
개인홈        로그인·캘린더·그룹 생성/참여
그룹홈        멤버·회의 입력·결과 UI
로직·통합     최적화·DB·테스트·Git 병합
```

**마지막 비전**

> 오늘은 다음 회의를 잡고, 앞으로는 팀의 반복되는 충돌을 먼저 발견해 조율합니다.

### 발표 대본

> “네 명이 화면, 조율 로직, 데이터 통합, 발표를 나눠 핵심 루프에 집중했습니다. 최적화 테스트 6개와 3개 페이지 검사를 통과했고, Browser Plugin으로 생성·가입·추천 흐름을 직접 검증했습니다. 현재 Calendar와 Gmail은 안전한 연결 경계를 마련한 단계이며, 실제 변경은 사람 확인 후 실행합니다. 오늘은 다음 회의를 정하지만, 장기적으로는 반복되는 충돌을 먼저 발견하고 해결하는 팀 운영 에이전트로 확장하겠습니다.”

### 마지막 10초

> **“Google Calendar가 일정을 관리한다면, 맞춰는 팀의 결정을 조율합니다.”**

# 5. 평가 기준과 발표 증거

| 평가 영역 | 배점 | 발표에서 보여줄 단 하나의 증거 |
| --- | ---: | --- |
| 문제 정의 및 사용자 가치 | 20 | 빈 시간 탐색이 아니라 충돌 시 의사결정 문제라는 슬라이드 1 |

| 데모 및 커뮤니케이션 | 5 | 5분 내 한 흐름으로 끝나는 발표 |

- [ ] 최종 웹사이트 URL 또는 확실한 로컬 실행 절차 준비
- [ ] 백업 시연 영상 로컬 저장
- [ ] Skill 실행을 별도 캡처 또는 로그로 보관
- [ ] Gmail을 핵심 Skill로 주장하려면 테스트 계정으로 dry-run 또는 draft를 실제 실행
- [ ] Plugin 사용 전후 결과 캡처
- [ ] API 키·토큰·개인 이메일이 영상에 없는지 확인

# 6. 발표 자료에서 삭제할 내용

다음 내용은 질문이 나왔을 때만 답한다.

- 풋살·스터디·택시 귀가 등 초기 아이디어 비교 과정
- 전체 DB ERD와 테이블 목록
- Google·Outlook 등 모든 캘린더 API 비교
- API와 Agent의 장시간 개념 논쟁
- 점수 공식의 모든 가중치
- 참여 코드의 해시·만료·사용 횟수 같은 DB 세부 구현
- 로그인·개인홈·그룹홈의 모든 UI 요소 소개
- 시장 규모, 비용 절감률, 정확도 등 검증하지 않은 숫자
- 일주일 리포트, 출석률 추적, 자동 중재 등 아직 데모하지 않는 장기 기능
- Skill·Plugin의 설치 과정

발표에서 기능 수가 아니라 다음 하나를 기억하게 한다.

> **전원이 가능한 시간이 없을 때도, 맞춰는 조정 가능성과 필수 참석자를 보고 다음 행동을 제안한다.**

# 7. 발표 직전 정합성 수정

현재 저장소에는 과거 이름인 `Featy/feet`가 일부 코드 식별자와 데모 코드에 남아 있다. 발표 화면에서는 사용자에게 보이는 브랜드를 모두 `맞춰(MatchU)`로 통일한다.

- 데모 코드 `FEATY20268`은 기능에는 문제가 없지만 브랜드와 맞지 않는다. 가능하면 `MATCH20268`처럼 영문 5자+숫자 5자 규칙을 유지한 코드로 교체한다.
- PPT에는 `Featy` 이름을 사용하지 않는다.
- 정적 웹 데모와 Next 프로토타입의 화면·데이터를 섞어 하나의 기능처럼 설명하지 않는다.
- 영상에서 사용하는 추천 결과와 발표 대본의 날짜·인원·상태가 같은지 확인한다.

## 최종 완료 조건

다음 질문에 모두 “예”라고 답하면 발표 준비가 끝난다.

1. 첫 20초 안에 기존 캘린더와 맞춰의 차이가 전달되는가?
2. Behavior, Context, Action, Goal, AI Tool이 하나의 인과 흐름으로 보이는가?
3. AI 없이 가능한 계산과 AI가 필요한 중재를 구분했는가?
4. 시연은 실제 작동하는 기능만 보여주는가?
5. Skill과 Plugin의 실제 사용 증거가 있는가?
6. 네 명의 역할이 결과물과 연결되는가?
7. 5분 안에 마지막 비전 문장까지 도달하는가?
